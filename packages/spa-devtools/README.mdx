# SPA devtools

An experimental atom.io debugger rendered with spa. The @atom.io/spa-devtools package powers the debugger on atom.io.fyi. It is separate from spa's renderer and size budget. Its root entry requires no React, Preact, or Motion; React integration is available through an optional entry.

Use spa's Vite or Astro integration to compile application JSX. Import the stylesheet once, then mount the debugger in a spa component:

<Setup />

The optional store prop selects the inspected store; it defaults to atom.io's implicit store. The debugger owns a rendering root in that store, so its parent island can use a different store. The store is fixed for an instance; use a different component key to inspect another store. Mounting is client-side, and Astro applications can use client:only with the spa renderer hint.

## Browser hosts

Use mountAtomIODevtools with a host element and optional store and hideByDefault options. The options are captured at mount; dispose and mount again to change them. Each call owns a child of the host and preserves its existing children. Call the returned dispose method when removing the debugger; repeated disposal is safe.

## React

Install the optional @atom.io/react and React 18 or 19 peers, and import AtomIODevtools from @atom.io/spa-devtools/react. It renders the same SPA debugger inside a React-owned host; application JSX needs no SPA compiler. Import @atom.io/spa-devtools/css once.

<ReactSetup />

The adapter reads StoreContext from @atom.io/react. An explicit store prop takes precedence over its provider; without either it uses the implicit store. Changing the selected store or hideByDefault disposes and remounts the panel. Persisted visibility takes precedence over hideByDefault. Effect cleanup supports StrictMode replay. Server import and render create no panel; mounting happens in a client effect.

The first four views inspect atoms, selectors, transactions, and timelines. State families group their members and offer member disposal. JSON editors support primitive edits, object property renaming, adding and removing entries, array sorting, and conversion between JSON types. Readonly selectors remain readonly. Circular and non-JSON values receive safe textual representations. Failed edits appear in the panel.

Transaction logs show parameters, output, and nested events. Timeline views group families, show event history and the current position, and provide store-scoped undo and redo. Logs use atom.io's introspection states: transaction recording starts when its log is first inspected, and introspection definitions live with the store.

Ctrl+Shift+A shows or hides the debugger. Drag the header to move the window, or drag any edge or corner to resize it. During a drag, hover a layout target to preview its exact viewport bounds before releasing: left/right halves, left/center/right thirds, top/bottom halves, or full viewport. The window-size button (□), between minimize and close, offers the same targets by keyboard, plus Restore free position. Focus the move handle or a resize handle and use arrow keys for 10-pixel adjustments. Snapped windows start those adjustments from their visible bounds; arrows unrelated to a resize edge or blocked by the viewport leave the snap unchanged. Escape, pointer cancellation, or capture loss restores the pre-gesture geometry; hiding, minimizing, unmounting, or replacing the store cancels active work. The last free position and snap choice persist in localStorage when available, and geometry clamps to the current viewport, including narrow screens. Geometry updates leave focused editor inputs and incomplete numeric text intact. Visibility, minimization, selected view, and expanded editors persist in localStorage when available. Shift-click an expansion button to expand or collapse siblings. UI-owned state uses disposable atom family members; unmounting releases those members, DOM subscriptions, and keyboard/resize listeners.

For a shared debugger UI, React applications can migrate their AtomIODevtools and stylesheet imports to this package's React and CSS entries. The existing @atom.io/react-devtools package remains available, including its JSON editor, elastic input, error boundary and customization contracts; those contracts are not exposed by the shared debugger.

The shared panel uses a static atom.io.fyi mark and a subtle noise texture, embedded in its stylesheet without animation or network requests. The view tabs have a separate row so window controls remain reachable; use Left/Right arrows or Home/End while a tab is focused, or scroll the tab strip in constrained windows. Editors retain 21–22 px rows. Keys, smaller type labels and values use consistent columns; long keys retain their full title. Text, numeric and property-name inputs grow with their contents. Numeric values align right within a nearby value column, borrowing key space for longer numbers; unfinished decimal text remains editable until blur. Opaque read-only values, including errors, can be focused and scrolled horizontally by keyboard or touch to read the full text. Transaction outcomes are indented beneath their labeled transaction, with changes nested one level further.

The stylesheet includes its own light/dark palette and Theia 0.3 fonts. It follows prefers-color-scheme. The shell and inactive tabs use explicit shades, active tabs and content use the normal surface, and search uses the first shade. Tint always means lighter and shade always means darker in both themes. The site's hard/soft aliases reverse with the theme; they are compatibility aliases, not drawer-depth numbers.

| Inactive tabs                | --surface-inactive, mapped to --bg-shade-1                   |

Drawer headers use the first, second and third shade as actual JSON nesting increases. At the third shade, deeper drawers keep that tone and use indentation/borders to communicate further nesting. This bounded three-tone policy keeps deep structures readable in both themes. Root editor rows remain 22 px and nested rows 21 px. Window gestures, numeric drafts and elastic input sizing retain their existing behavior.

The bundled Theia weights are 200 for lightweight headings, 400 for body/control text and 500 for emphasis. The private font-family name Atom IO Theia avoids accidentally resolving an ambient site installation. Font synthesis is disabled. The original files were authored by Jeremy Banka and are distributed under MPL-2.0; their source paths, hashes and preserved copyright notices are recorded in the packaged fonts/PROVENANCE.json and fonts/LICENSE beside the stylesheet. Font URLs are relative to the emitted CSS, so root and subpath hosting work without requests to atom.io.fyi. Serve the emitted fonts directory with the stylesheet; no system font or root-level site assets are required.

The debugger and storefront use component-owned Lasertag CSS Modules with one class export and named roots. SPA components render the complete debugger, including search results, the ecology graph and inspector, and the window layout palette. Controllers schedule capture and matching, handle gestures and restore focus after SPA commits. Global CSS contains the shared theme tokens, fonts and scoped resets. The emitted stylesheet needs no Lasertag runtime, CSS Modules loader or site build configuration.

## Search across debugger views

Each view has its own local search and query text. Opening a view or pressing Refresh takes an explicit capture; subsequent queries use that admitted copy. Queries survive navigation within the mounted debugger. Changing a query never refreshes the store, evaluates a dormant selector, initializes a family member, invokes an application callback, replays a transaction or moves an undo/redo cursor. If a transaction is currently applying, capture waits for its commit. Capture time and omission notices describe what was actually searched, rather than promising a current or complete view of the application.

| View         | Searchable data                                                                                                                        | What selecting a result does                                                                |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Atoms        | Keys, family keys and serialized subkeys, token/cache metadata, and cached strings, numbers, booleans, null or undefined               | Shows passive captured metadata and offers the existing live editor                         |
| Selectors    | The same fields as atoms, including readonly/writable and observed/unknown dependency metadata                                         | Shows passive captured metadata; an explicit live-editor action may evaluate the selector   |
| Transactions | Log and affected state keys, event types, family/subkeys, and bounded primitive previews of recorded parameters, outputs and updates   | Reveals the recorded event in its original chronological log context                        |
| Timelines    | Timeline/family/subkeys and the same recorded event fields, across retained history on both sides of the cursor                        | Reveals an event without seeking, undoing or redoing                                        |
| Ecology      | Captured keys, family keys/subkeys, token types and cached runtime kinds, including already instantiated members of collapsed families | Selects metadata and focuses its graph/list entry, preserving pan/zoom and family expansion |

The atoms/selectors views also contain ordinary live rows. Those rows can read state when the view or an editor mounts; that existing behavior is distinct from passive search. Transactions begin ordinary outcome recording when their logs are opened, so earlier outcomes are not recoverable through search. Timeline history is retained application history, not a complete audit log. Ecology never searches cached scalar contents: a cached object is searchable by its kind, without inspecting its properties or inferring a promise's completion state. Only its explicit Open live editor action may read or evaluate application state.

Search summaries keep match counts, capture time, nonzero uncached/skipped-value counts and truncation warnings visible. Capture details retains skipped-value counts and the full recording qualifications in a keyboard-accessible disclosure. Ecology groups its capture explanation and shape legend in the same way, while marking truncated captures in the disclosure label. Empty graph searches explain how to restore the capture, and selections outside the current view are labeled as retained. A history search with no matches keeps the recorded tree visible and labels it as unchanged by search.

### Matching and keyboard navigation

All five views use Unicode NFKC normalization and case folding, with word boundaries including camel-case identifiers. Multiple query words must all match the record, possibly across different fields. Key/family matches rank ahead of incidental metadata/value matches; exact keys and literal matches precede limited one-edit approximations. Ties follow stable capture order. For example, “checkout total” can find checkoutTotalCents, and an ecology query can combine a family name with an instantiated member's subkey. Approximate results are labeled. Oversized queries produce a validation message while leaving the last valid display in place.

Use Ctrl/Cmd+Shift+F, or slash outside an editable field, to focus the current view's search. Native Ctrl/Cmd+F and composition input remain available. Up/Down visits ranked results, Home/End visits the first/last result while a result is focused, and Enter selects. Escape in results returns to search; in the search input it first clears the query, then returns focus to the prior control or retained draft. Escape used to cancel a window gesture takes precedence.

Transaction/timeline results identify their owning log and chronological event position. A result whose recorded event moved or disappeared after history collection is marked stale; Refresh updates it. Ordinary log rows and subscriptions remain mounted during search. Selecting an event does not reorder history or execute an application action.

Ecology uses one search surface for both ranked results and graph filtering. It keeps full captured counts, known matching counts, up to 100 ranked results and up to 500 painted groups/instances distinct. Selecting a ranked result opens the accessible list and keeps the selected match reachable even beyond the ordinary paint cap. Searching within a collapsed family does not expand it or create members; the selected member remains reachable after clearing the query. Query changes preserve selection, retained tracing and pan/zoom. Escape first clears the ecology selection while retaining the query; from the accessible list, ranked results or inspector heading it also returns focus to search. With no selection, subsequent Escape presses clear the query and return focus to the prior control or retained draft. Clear search and Clear selection have separate effects. Clear the query to restore broader captured graph context around a trace.

### Live editing, freshness and omissions

Searching preserves unfinished editing text and selection. In ecology, an open live editor stays mounted in its labeled editing area while queries, passive selections and Refresh update the graph and metadata inspector. Returning to it restores the draft. Opening another live editor or leaving the passive search area uses ordinary edit validation/blur behavior; Back to passive inspector closes the ecology editor. A disposed or replaced backing definition invalidates the retained editor instead of applying its old draft to another state. Live store updates can still invalidate an editor through the normal state lifecycle.

Search copies only bounded metadata and allowed primitives. Opaque objects, arrays passed as parameter values, functions, symbols, bigints and promises are skipped without enumeration, serialization hooks or awaiting. Ordinary recorded-event previews use the same primitive-only rule. A capture or text prefix can be incomplete; zero matches means no known match in that captured, admitted data. A plus sign on an approximate matching count denotes a lower bound when the comparison budget was exhausted. Refresh explicitly recaptures; application activity alone does not make a passive snapshot current.

| Limit                   | Atoms/selectors                                                                                                | Transactions/timelines                                                                                                     | Ecology                                                                       |
| ----------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Source capture          | Up to 10,000 application nodes, 10,000 family records and 50,000 relation inspections                          | Up to 200 log records, 10,000 event references and 32 nested event levels                                                  | The same node/family/relation capture limits as atoms/selectors               |
| Admitted search records | Captured definitions and family metadata                                                                       | Up to 5,000 log/event records; stop admitting after 500,000 copied characters with at most one bounded record of overshoot | Captured family and node metadata, including members hidden by graph collapse |
| Text and indexing       | At most 1,024 characters per field, 2,048 per record and 16 indexed words per record                           | The same bounds; only the first 16 transaction parameters are considered, and oversized log keys omit their history        | The same field/record/word bounds; no scalar application values copied        |
| Query and results       | At most 256 query characters/eight words; two million approximate-comparison work units; up to 100 ranked hits | The same limits                                                                                                            | The same limits, with known matching IDs kept separately for graph filtering  |

These are finite prefix captures, not ranked samples of omitted store data. Text-prefix, capture and approximation notices qualify the displayed counts. Full store totals remain unknown after a truncated capture. Work is cancellable during metadata indexing, matching and graph projection; new input supersedes old queries, and hidden, minimized, switched or disposed views stop scheduled work. No polling or automatic application-graph subscription is introduced.

## Ecology explorer

The ecology tab captures an observed snapshot on entry and Refresh. SPA’s Three.js Canvas places atoms and atom families on a descending helix around an invisible cylinder whose diameter-to-height ratio follows the Three.js canvas. Wide canvases produce wider cylinders, and narrow canvases produce taller cylinders. Resizing preserves orbit direction and relative zoom without recapturing application state. Selectors and selector families ascend on a parallel helix that stays 180° opposite the atom helix at the same height. Angles use the same top-to-bottom reference, so building selectors upward does not make the paths cross. DOM cards face the viewer and show names, readable categories (Atom, Atom Family, Selector or Selector Family), and cached kinds or member counts; dashed cards identify families, including empty definitions. A digest of each family or singleton key gives its border and outgoing arrows a stable color through the card’s `--ecology-color` CSS variable and matching WebGL vertex colors. Family members inherit their family’s color. Atom hues occupy the warm half of the spectrum (270° through red to 90°); selector hues occupy the cool half (90° through blue to 270°). Colors have 75% HSL saturation, with lightness balanced for contrast in both themes. Clustered members occupy small, deterministic offsets around their family’s center, with their individual cards hidden. Each painted dependency remains a separate, softly translucent 3D curve and arrowhead, so connections overlap into a darker core with a lighter fringe while staying attached to the visible family card. Overlapping edges accumulate opacity. Expanding a family spreads its members along the cylinder’s tangent; collapsing returns their endpoints to the group. Selecting a ranked member result expands its family and focuses the camera. Search uses the shared ranked metadata matcher described above. The graph paints at most 500 nodes and 1,000 directed arrows. The info button opens a dismissible, scrollable guide containing navigation instructions, capture details and the legend on every screen size. Search narrows the captured snapshot while retaining the selected match and inspector state. A capture truncated by the snapshot API explicitly reports that full store totals are unknown.

Selection opens a passive metadata inspector and emphasizes every captured path upstream and downstream of the selected node. These walks stay separate: an ancestor’s other consumers and a descendant’s other roots remain unrelated. Connected edges become more opaque while retaining their source colors and draw after background edges. Active cards stack above unrelated cards, with the selected card foremost; distance orders cards within each tier. Unrelated cards fade to 50% opacity. Selecting a family traces from its captured members, keeping collapsed groups visible when any member is connected. Trace observed roots reports atom roots and unknown, missing, cyclic or truncated evidence. Cached kinds are shallow; asynchronous wrappers can appear as object and their completion status is unknown. Selection, searching, tracing and expansion never read application state. Only the explicit Open live editor action mounts the existing editor and may read or evaluate that state; readonly selectors stay readonly. Back returns to passive inspection.

At debugger widths of 650 px or less, Graph, Node list and Selection buttons give each workspace the full available width. This follows the debugger window's width, including a narrow free window on a wide desktop. Selecting a node or ranked result opens Selection and focuses its heading; Escape from that heading clears selection and focuses the search button. The square icon toolbar contains Search, Refresh, Clear selection, Fit, Reset view and the guide. Search opens a modal on these narrow views; a colored dot on its button indicates an applied filter. Dismissing the modal keeps the filter, and Clear search restores the captured graph. In wider windows, search stays in the toolbar and ranked results open below the field without resizing the graph. The same field and results stay mounted across resizing. Modals support Escape, a close button and backdrop dismissal, contain keyboard focus, and return focus to their invoker or the retained editor draft. Wider windows show the graph/list beside the inspector. Switching workspaces keeps search, the camera, the captured snapshot and any explicit live editor mounted. Passive navigation preserves unfinished editor text; Back to passive inspector closes that editor and returns focus to its opening control.

The Storybook Storefront story presents the order-fulfillment model as a small pantry: catalog stock, cart quantities and line totals, fulfillment fees, a coupon, and undo/redo all use the same isolated store as the debugger. Ecology Sandbox opens that storefront directly to the ecology view without running application actions, searches or selections, making it a quiet starting point for development. Stock follows the selected warehouse; changing delivery to pickup changes the fee's observed roots. Unavailable cart lines remain visible so another warehouse can be tried. Scenario controls contain the local carrier-quote outcomes and reset. The storefront is the page itself, in normal document flow. Use Ctrl+Shift+A to show or hide the floating debugger, or its close button to return to browsing. The story starts with six cart lines, and Reset creates a fresh store. There are no checkout services or network calls, and passive graph/search navigation leaves the deliberately dormant promotion, lazy audit and empty wishlist untouched.

The accessible node list and graph nodes support keyboard selection. Escape clears selection and its emphasis. Enter toggles clustering and expansion when a family or family member is selected, from its card, accessible-list row, inspector heading or the focused graph. Member selection and keyboard focus follow the visible family card while clustered and return to the member on expansion. The Collapse family button folds it again. The Fit and Reset view icons position the graph. With the graph focused, arrow keys pan and +/− zoom. Standard OrbitControls provide left-drag orbit, right-drag pan, wheel zoom, one-finger orbit, and two-finger pan/pinch zoom. The initial view fits the viewport-shaped cylinder, while very long family expansions start at a readable section. Fit shows the entire painted graph, and search brings a selected result into view. Cards may overlap in the projection; orbit, pan, zoom or use the accessible list to reach them. When WebGL is unavailable, the list, search and passive inspector remain available. Selection, family expansion and the camera survive navigation; value-only refresh preserves positions. Topology changes recompute the evenly spaced helices. Ordinary application reads can change observed dependencies without a notification: Refresh is explicit, with capture time in the guide. There is no polling or automatic graph subscription. Hidden, minimized and unmounted views cancel pending work. Window geometry reshapes the cylinder locally without requesting capture or repeating metadata indexing and graph projection.

## Ecology snapshots

captureEcologySnapshot provides a data-only foundation for an ecology explorer; it adds no graphical view. It inspects the supplied root store's committed maps without following an active transaction child. Capture never calls state getters, initializes defaults or family members, attaches introspection subscriptions, or awaits promises. It returns detached metadata with store-local keys, token kinds, family keys and serialized subkeys, cached runtime types, and retained directed dependency edges. Values and live tokens are omitted.

<Ecology />

A cached value has status cached, including a cached undefined; an absent cache has status unknown. Runtime type inference is deliberately shallow: typeof, null and array, with unknown for an uninspectable revoked proxy. Objects, class instances and asynchronous wrappers remain object; their prototypes, properties and resolved values are not inspected. These are runtime observations, not declared TypeScript types.

Selector dependencies are unknown when neither a cached result nor inbound observations exist. An evaluated constant can have observed dependencies with zero edges. Observed edges describe only the runtime graph's retained observations: they can be partial after a failed or asynchronous evaluation, or belong to a previous branch after invalidation. They are not a static dependency declaration or a promise about the next evaluation. Reserved introspection nodes and families are excluded, but dependency edges to missing or excluded nodes retain their keys so root tracing reports uncertainty. Family member counts cover registered, instantiated members, including empty registered families; a token obtained with findState alone need not instantiate a member.

Capture defaults to returning at most 1,000 application nodes, inspecting 1,000 family records and inspecting 5,000 neighboring graph relations. The node allowance excludes reserved debugger records. Total state inspections remain bounded at the node allowance plus 1,000 records; a zero node allowance performs no state inspections. The extra headroom covers excluded records and a possible omitted-node probe. Bounded tail inspection distinguishes a filtered-only tail from an application node beyond the allowance. The reported work.nodes counts actual inspections, so it can exceed the application-node allowance. Node, family and relation options accept nonnegative integers up to ceilings of 10,000, 10,000 and 50,000 respectively. Family inspections still charge excluded records; relation inspections still charge reverse-direction and excluded neighbors. Results expose actual inspection counts, truncation flags and per-selector dependency truncation; node truncation means an application node was omitted or the finite inspection bound left records unknown. Family counts are lower bounds when state capture truncates. Iteration follows store insertion order, so a truncated snapshot is a bounded prefix rather than a ranked sample. No sorting or recursive value traversal runs during capture.

traceEcologyRoots follows the captured edges iteratively, deduplicates shared roots, and reports unresolved keys and cycle back-edge destinations. Its default 50,000 work units include snapshot indexing and traversal, with a configurable ceiling of 1,000,000. Status observed means the retained graph traversal finished; incomplete means some visited dependency is unknown, missing or truncated; truncated means the trace budget ran out. None of these statuses establishes complete static dependencies. Capture again after application activity to obtain new observations; snapshots are not subscriptions.

## Package checks

Tsdown builds the package JavaScript and declarations. SPA's compiler transforms the debugger JSX before bundling, preserving reactive bindings. The build bundles the component styles into the existing CSS entry and copies its declaration and the three licensed font assets alongside the JavaScript; SPA and atom.io stay external peers.

Breakage exercises the packed package in isolated, locked peer environments, including the coordinated atom.io workspace candidate. Until the first published release, Breakage reports a first-release baseline; these checks establish compatibility with the declared peers rather than a previous spa release. Coverage gates require 100% of statements, branches, functions, and lines across the package source.

The serving recipe measures an interactive SPA app with the debugger: atom creation, render, useGetter, useSetter, JSX, and AtomIODevtools. The combined browser bundle includes atom.io, SPA, and the debugger, with shared modules counted once and unused exports removed. The graphics module loads when ecology opens; other views and data-only imports do not initialize Three.js. The measurements below include that deferred graphics code. SPA and atom.io remain peer dependencies of the debugger package; these consumer-app measurements include both. The required debugger stylesheet is imported but its bytes and the bundled fonts are excluded from the JavaScript total, as are application components, declarations, and source maps.
