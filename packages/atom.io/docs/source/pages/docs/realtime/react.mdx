# <low-emphasis>atom.io</low-emphasis>/realtime-react

`atom.io/realtime-react` binds the renderer-neutral services from
[`atom.io/realtime-client`](/docs/realtime-client) to React lifecycle. Its hooks
render ordinary atom.io Store state; they do not create a second replica model.

## provider and service ownership

<Exhibit src="realtime/provide-realtime-react.tsx" />

`RealtimeProvider` supplies one Socket.IO client and coalesces services by
stable key. Nest it inside the Store/Silo provider whose atoms participate in
collaboration. Replacing the socket disconnects old services and lets them
reconnect through the new transport.

Use the current origin for browser connections when a Vite, reverse proxy, or
edge worker forwards the realtime route to the backend. The server must still
validate the handshake origin, authenticate the credential, and apply admission
and rate limits.

`useRealtimeService` starts one keyed headless service for the lifetime of its
consumers. It disposes that service only after the last matching consumer
unmounts. Keep the service key and factory stable enough to express that
ownership deliberately.

Pull hooks subscribe only while consumed. Push hooks expose lease ownership and
status so the UI can distinguish pending, owned, and denied publication.

## Mosaic hooks

`useMosaic` owns one `MosaicController` created by `syncMosaic`. It exposes
commands and status; render the mutable atom itself through normal atom.io hooks.

<Exhibit src="realtime/synchronize-a-mosaic-value.tsx" />

`useMosaicTextRange` acquires a projected viewport plus overscan through a
`MosaicTextProjectionClient`, updates the acquisition as the viewport moves,
and releases it on unmount.

## lifecycle rule

The provider, socket, service keys, and surrounding Store/Silo define ownership.
Do not open sockets or construct controllers during render. Late asynchronous
responses after disposal must not update the replacement service or Store.
